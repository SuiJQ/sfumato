# 04 · 打包与离线

> 目标：双击即用、全程不联网。本文只写实际可执行的步骤，不含未验证的配置。

---

## 1. 为什么不能直接双击 index.html

`file://` 下 Worker、WASM、`fetch` 本地文件会被 CORS 拦死。必须走 `http://`。

三种可行形态：

| 形态 | 真·零网络 | COOP/COEP | 适用 |
|---|---|---|---|
| 本机静态服务 | ⚠️ 走 localhost | 可自行注入 | 开发、日常自用 |
| Tauri 打包 | ✅ | ✅ 可设 | 推荐，双击即开 |
| PWA + Service Worker | ✅（首次之后） | 需 https/localhost | 需要托管时 |

---

## 2. 本机静态服务（最快上手）

```bash
cd photo-tool
NODE_ENV=development npm install --include=dev
NODE_ENV=development npm run build
python3 -m http.server 4173 --directory dist
# 打开 http://127.0.0.1:4173/
```

> `NODE_ENV=development` 必须带：本机环境若设了 `NODE_ENV=production`，
> npm 会跳过 devDependencies，`tsc` / `vite` 都不会被安装。

也可以用 `npm run preview`（Vite 自带静态服务）。

## 3. Tauri v2 打包

### 3.1 前置

```bash
rustc --version          # 需要 1.77+
cargo install tauri-cli --version "^2"
```

### 3.2 初始化

```bash
cd photo-tool
npm i -D @tauri-apps/cli@^2
npx tauri init
```

初始化时填写：

- 前端产物目录：`../dist`
- 开发服务器：`http://localhost:5173`
- 构建命令：`npm run build`

### 3.3 关键配置（`src-tauri/tauri.conf.json`）

```jsonc
{
  "build": {
    "beforeDevCommand": "npm run dev",
    "beforeBuildCommand": "npm run build",
    "devUrl": "http://localhost:5173",
    "frontendDist": "../dist"
  },
  "app": {
    "windows": [{ "title": "Grain", "width": 1440, "height": 900 }],
    "security": { "csp": null }
  }
}
```

### 3.4 注入 COOP/COEP（决定推理速度）

没有这两个头，`SharedArrayBuffer` 不可用，onnxruntime 只能单线程跑
（本机实测 384px 单线程约 0.6–2s，可接受但不是最优）。

Tauri v2 里在 `src-tauri/src/lib.rs` 的自定义协议响应上追加响应头：

```rust
// 伪代码，具体 API 以当前 tauri 版本为准
tauri::Builder::default()
    .register_uri_scheme_protocol("grain", |_app, request| {
        let mut response = tauri::http::Response::new(read_asset(request.uri()));
        response.headers_mut().insert(
            "Cross-Origin-Opener-Policy", "same-origin".parse().unwrap());
        response.headers_mut().insert(
            "Cross-Origin-Embedder-Policy", "require-corp".parse().unwrap());
        response
    })
```

验证：打开 devtools，`crossOriginIsolated` 应为 `true`。

> 不要把这一步当成必做项。**单线程能跑通，就不该为一个优化牺牲打包稳定性**。
> 想先要可用版本，跳过 3.4。

### 3.5 打包

```bash
npm run build
npx tauri build
```

产物在 `src-tauri/target/release/bundle/`。

### 3.6 模型随包分发

`public/models/` 与 `public/ort/` 会被 Vite 原样复制进 `dist/`，
Tauri 打包时一并进入安装包（约 +22MB）。无需任何下载逻辑。

## 4. 离线验收（必做）

1. 断网（或关掉所有网络接口）
2. 启动应用
3. 依次验证：
   - [ ] 打开 JPEG / PNG
   - [ ] 拖六根滑杆，画面实时变化
   - [ ] 人像优化 / 天空增强 自动勾选（说明模型加载成功）
   - [ ] 导出 JPEG，文件可被系统看图软件打开
   - [ ] 存预设 → 重启 → 预设仍在

任何一步失败，先查 devtools 的 Network 面板：**出现任何外部域名都是 bug**
（最常见的是 onnxruntime 默认回退到 jsdelivr）。代码里已用
`ort.env.wasm.wasmPaths` 指向本地绝对路径，若仍外连，检查 `new URL(..., document.baseURI)` 是否正确。

## 5. 体积清单

| 项 | 大小 |
|---|---|
| 应用代码（JS + CSS + shader） | ~210 KB |
| `ort/ort-wasm-simd-threaded.wasm` | 15 MB |
| `models/modnet_int8.onnx` | 6.6 MB |
| `models/face_landmarker.task` | 3.6 MB |
| `vision/vision_wasm_internal.wasm` | 14 MB |
| **合计** | **~40 MB** |

FaceMesh 的 18MB 是整套 tasks-vision 运行时的代价（其中 14MB 的 wasm 覆盖所有视觉任务，
目前只用了人脸）。如果以后想瘦身，可以换成 ONNX 版的人脸关键点模型复用 ORT，
但会牺牲检测鲁棒性——现阶段不值得。

`public/ort/` 里只保留 `ort-wasm-simd-threaded.{wasm,mjs}` 两个文件。
其余 `asyncify / jsep / jspi / webgl / webgpu` 变体全部删除——它们是给别的后端用的，
留着会让安装包膨胀到 100MB。

## 6. 已知限制

- 只支持 JPEG / PNG；HEIC、RAW、WebP、AVIF 一律拒绝（有明确提示）
- 导出只有 JPEG（q=0.93），PNG 的透明区域会被白底铺平
- 不嵌入 ICC，输出按 sRGB 解释
- 大于 50MP 的图片直接拒绝；超过显卡纹理上限时导出会等比缩小
- 未接入 FaceMesh，皮肤 mask 由 `人像 ∩ 肤色先验` 得到
